# API quick reference

Last checked: 2026-10-26 (the `ArrangementView` reference, read via its `.md` endpoint, lists availability iOS 27.1.0; the Xcode 27.1 release notes and the Technology Overview were re-fetched the same day and match the wording quoted below)

One table of the iOS APIs that matter for iPhone Duo, grouped by purpose, with the SwiftUI and UIKit (or AVFoundation, Core Motion, Info.plist) form side by side. Symbol names are copied from Apple's documentation and Tech Talk code, not paraphrased. Where a name came from somewhere else, the Status column says so.

## How to read the Status column

- **Apple**: the symbol, signature or behaviour appears on an Apple documentation page, in Apple's Tech Talk code, in Apple release notes, or in an Apple engineer's Developer Forums post. Safe to cite.
- **third-party, unverified**: the name or detail comes from a community repo, blog, or simulator observation and has not been confirmed on an Apple page. Check it against the SDK headers before relying on it.
- **inferred**: a conclusion drawn from Apple's statements rather than stated by Apple. For example, Apple's `AVCaptureDeviceDirectionCoordinator` example shows the initializer in use; the exact Swift signature and availability annotations were not captured from a reference page.
- **mixed**: the row contains items of more than one status; each item is labelled inline.

Availability, per Apple: all Duo-specific symbols are annotated iOS 27.1+ / iPadOS 27.1+ (SwiftUI symbols also list macOS, tvOS, visionOS, watchOS 27.1; UIKit symbols list Mac Catalyst, tvOS, visionOS 27.1), except scene accessories in UIKit, which are iOS 27.0+ ([ArrangementView](https://developer.apple.com/documentation/swiftui/arrangementview); [UISceneAccessory](https://developer.apple.com/documentation/uikit/uisceneaccessory)). The APIs are "Available on any iPhone or iPad running iOS 27.1+, not exclusive to iPhone Duo" ([Apple Developer Forums 847644](https://developer.apple.com/forums/thread/847644)). "existing" in the Min OS column means the API predates iOS 27.

## Reference pages for each row

- Reserved regions: [GeometryProxy.reservedRegions](https://developer.apple.com/documentation/swiftui/geometryproxy/reservedregions(kind:options:layoutdirectionbehavior:)); [UIView.reservedRegions](https://developer.apple.com/documentation/uikit/uiview/reservedregions(kind:options:)). Note that the Tech Talk 111461 summary calls the UIKit type `UIViewReservedRegion` while the docs and HIG spell it `UIView.ReservedRegion`; the doc spelling is authoritative.
- Arrangements: [ArrangementView](https://developer.apple.com/documentation/swiftui/arrangementview); [UIArrangementViewController](https://developer.apple.com/documentation/uikit/uiarrangementviewcontroller).
- Hinge: [onHingeChange(isEnabled:_:)](https://developer.apple.com/documentation/swiftui/view/onhingechange(isenabled:_:)); [DeviceHinge](https://developer.apple.com/documentation/swiftui/devicehinge); [UIHingeInteraction](https://developer.apple.com/documentation/uikit/uihingeinteraction); [UIHinge](https://developer.apple.com/documentation/uikit/uihinge). Note the unit mismatch: SwiftUI `Angle`, UIKit radians.
- Vertical bars: [Preparing your app for iPhone Duo](https://developer.apple.com/documentation/technologyoverviews/preparing-your-app-for-iphone-duo); [Tech Talk 111462](https://developer.apple.com/videos/play/tech-talks/111462/); [UITraitCollection.verticalBarEdge](https://developer.apple.com/documentation/uikit/uitraitcollection/verticalbaredge); [toolbarVerticalBehavior(_:)](https://developer.apple.com/documentation/swiftui/view/toolbarverticalbehavior(_:)) (URL reported by a third party). One discrepancy to check in headers: the 111462 slide shows `leftItemsSupplementBackButton` while narration says `leftItemSupplementsBackButton`.
- Scene accessories: [UISceneAccessory](https://developer.apple.com/documentation/uikit/uisceneaccessory); [CameraCaptureAccessory](https://developer.apple.com/documentation/swiftui/cameracaptureaccessory); [Registering a camera capture accessory on iPhone Duo](https://developer.apple.com/documentation/avfoundation/registering-a-camera-capture-accessory-on-iphone-duo).
- Camera: [Choosing a camera by the direction it faces](https://developer.apple.com/documentation/avkit/choosing-a-camera-by-the-direction-it-faces) (AVKit module); [Tech Talk 111465](https://developer.apple.com/videos/play/tech-talks/111465/). One repo reports `AVCaptureDeviceDirectionCoordinator` absent from the headers of the 27A9269 beta SDK; verify against 27A9275.
- Scene geometry and Info.plist keys: [TN3192](https://developer.apple.com/documentation/technotes/tn3192-migrating-your-app-from-the-deprecated-uirequiresfullscreen-key).
- Motion: [Apple Developer Forums 847644](https://developer.apple.com/forums/thread/847644).
- Compile guards: Mac Catalyst builds that use iOS 27.1-only APIs produce compile errors (185924957; workaround `#if !targetEnvironment(macCatalyst)`), and targeting iOS 27.1 shows no Catalyst run destination (187046347; workaround: add a Mac Catalyst 27.0 minimum deployment) ([Xcode 27.1 Release Notes](https://developer.apple.com/documentation/xcode-release-notes/xcode-27_1-release-notes)). The `canImport` version guard is third-party, unverified: `#available(iOS 27.1, *)` is not enough under Xcode 27.0 because the symbols are missing at compile time, and `#if compiler(>=6.4)` cannot distinguish SDKs ([blakecrosley.com](https://blakecrosley.com/blog/prepare-your-app-for-iphone-duo)).

What does not exist, per Apple: no pose API, no Duo idiom, no Duo Info.plist key, no `simctl` fold command, and no Apple sample project ([Apple Developer Forums 847644](https://developer.apple.com/forums/thread/847644); [Tech Talk 111461](https://developer.apple.com/videos/play/tech-talks/111461/)). Open questions about this table are tracked in known-gaps.md.
